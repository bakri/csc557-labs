    What you will learn

    By the end of this lab you will be able to:

    • explain the difference between match_parent, wrap_content, 0dp and fixed dp sizes;
    • arrange views in rows and columns with LinearLayout and share space with layout_weight;
    • position views relative to each other with RelativeLayout (legacy, but still common in older code);
    • tell gravity apart from layout_gravity, and margin apart from padding;
    • build a screen that adapts to different devices with ConstraintLayout, using the Layout Editor and reading the XML it generates.

    Three things that save time

    Watch out

    1. Keep android:id="@+id/main" on the root layout. The Empty Views Activity template generates MainActivity.java with this line:

    MainActivity.java
    ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> { ... });

    It looks up the root layout by the id main so that your content is not drawn under the status bar. If you replace the layout and forget the id, the project will not compile (cannot find symbol: main), or the app will crash at start-up if the id is used for a different view. Every complete layout in this lab keeps that id.

    2. Code view vs Design view. The buttons at the top right of the layout editor switch between Code, Split and Design. Split is the most useful view for this lab: you type XML on the left and see the result on the right.

    3. Yellow highlights in the code blocks mark lines that are new or changed in that step. You only need to type those lines. The Copy button copies the whole block.

    Activity 1: Create a project and a LinearLayout

    A LinearLayout places its children one after another in a single column (vertical) or a single row (horizontal). In this activity you will see how the size of each child decides what fits on the screen.

    1. Start Android Studio and choose New Project.
    2. Choose the Empty Views Activity template, then click Next. (Do not pick Empty Activity, which creates a Jetpack Compose project without XML layouts.)
    3. Name the project (for example LabActivity1), set Language to Java, keep Minimum SDK at the suggested value (API 24 or above), and click Finish. Wait for the Gradle sync at the bottom of the window to finish before you continue.
    4. Open the layout file for the main activity: app › res › layout › activity_main.xml.

      The file opens in Design view. Switch to Code (or Split) with the buttons in the top right corner.

    5. The template uses a ConstraintLayout as the root. Change it to a LinearLayout, remove the four app:layout_constraint... lines from the TextView (they only work inside a ConstraintLayout). Keep the "Hello World!" text. Your file should now look like this:
      res/layout/activity_main.xml
      <?xml version="1.0" encoding="utf-8"?><LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"    xmlns:tools="http://schemas.android.com/tools"    android:id="@+id/main"    android:layout_width="match_parent"    android:layout_height="match_parent"    tools:context=".MainActivity">​    <TextView        android:layout_width="wrap_content"        android:layout_height="wrap_content"        android:text="Hello World!" />​</LinearLayout>
    6. Switch to Design (or look at the Split preview). “Hello World!” appears in the top-left corner. Now press the green Run ▶ button once to launch the app on the emulator, so you know your setup works.

    1. A TextView is a rectangle, but you cannot see its edges. Add a green background so you can:

    Activity 1: Weights and nesting

    Exercise 1 asks for two new ideas: sharing a row with weights, and putting one LinearLayout inside another. You will try both here, step by step, on the same project.

    1. Your row of three boxes is still there, each wrap_content wide. To make the boxes share the whole row, set every TextView's layout_width to 0dp and give each one layout_weight="1":
      res/layout/activity_main.xml
      <TextView    android:layout_width="0dp"    android:layout_height="wrap_content"    android:layout_weight="1"    ... />

      The three boxes are now exactly the same width and together fill the row. 0dp means “I take no width of my own”, and the weights decide how the free space is shared: 1 + 1 + 1 = 3 shares, so each box gets one third.

    Predict first

    In the next step the first box gets layout_weight="2" and the other two keep 1. What fraction of the row will the first box take?

    1. Change the weight of the first TextView only:
      res/layout/activity_main.xml
      <TextView    android:layout_width="0dp"    android:layout_height="wrap_content"    android:layout_weight="2"    android:text="Hello World!"    android:background="#0F0" />

      The green box is now twice as wide as each of the others. There are 2 + 1 + 1 = 4 shares, so it takes half the row and the other two take a quarter each.

    2. Now nest one layout inside another. A single LinearLayout is either a column or a row, but many screens need both: a column of fields with a row of buttons at the bottom. You get that by putting a horizontal LinearLayout inside a vertical one. Replace the whole file with the layout below:
      res/layout/activity_main.xml
      <?xml version="1.0" encoding="utf-8"?><LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"    xmlns:tools="http://schemas.android.com/tools"    android:id="@+id/main"    android:layout_width="match_parent"    android:layout_height="match_parent"    android:orientation="vertical"    tools:context=".MainActivity">​    <EditText        android:layout_width="match_parent"        android:layout_height="wrap_content"        android:hint="Search"        android:inputType="text" />​    <LinearLayout        android:layout_width="match_parent"        android:layout_height="wrap_content"        android:orientation="horizontal">​        <Button            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="1"            android:text="OK" />​        <Button            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="1"            android:text="Cancel" />​    </LinearLayout>​</LinearLayout>
    3. Look at the preview and match it to the XML:
      • The outer, vertical LinearLayout stacks two children: the EditText, then the inner LinearLayout.
      • The inner, horizontal LinearLayout puts the two Buttons side by side, and their equal weights make them the same width.
      • An EditText is a text field the user can type into. hint is the grey text shown while the field is empty, and it disappears as soon as the user types.
      • inputType tells Android what kind of text to expect. text is ordinary text; textPassword shows dots instead of the letters.

    Checkpoint

    • Why does a view that uses layout_weight in a row get layout_width="0dp"?
    • Two buttons have weights 2 and 1. What fraction of the row does each one get?
    • Which LinearLayout in step 18 decides that the buttons sit below the field, and which decides that they sit beside each other?

    Activity 2: Relative Layout

    In a RelativeLayout each child is positioned relative to its parent or to a sibling: below it, to the left of it, aligned with its right edge, and so on. RelativeLayout is a legacy layout. New screens normally use ConstraintLayout (Activity 4), which does the same job better, but you will still meet RelativeLayout in older projects and tutorials, and its ideas carry straight over to ConstraintLayout.

    1. Create a new project with the Empty Views Activity template (Java).
    2. Replace the whole content of activity_main.xml with the following:
      res/layout/activity_main.xml
      <?xml version="1.0" encoding="utf-8"?><RelativeLayout xmlns:android="http://schemas.android.com/apk/res/android"    xmlns:tools="http://schemas.android.com/tools"    android:id="@+id/main"    android:layout_width="match_parent"    android:layout_height="match_parent"    tools:context=".MainActivity">​    <TextView        android:id="@+id/textView1"        android:layout_width="match_parent"        android:layout_height="wrap_content"        android:background="#0F0"        android:text="Hello World!" />​    <TextView        android:layout_width="wrap_content"        android:layout_height="wrap_content"        android:background="#00F"        android:text="Hello World!"        android:layout_below="@id/textView1" />​</RelativeLayout>

      @+id/textView1 creates a new id. @id/textView1 (without the +) refers to an id that already exists.

    3. Look at the output. The second TextView sits below the first one because of layout_below.
    4. Now also align the right edge of the second TextView with the right edge of the first one:
      res/layout/activity_main.xml
      <TextView    android:layout_width="wrap_content"    android:layout_height="wrap_content"    android:background="#00F"    android:text="Hello World!"    android:layout_below="@id/textView1"    android:layout_alignEnd="@id/textView1" />

      alignEnd means “right edge” in left-to-right languages and “left edge” in right-to-left languages such as Arabic. Older code uses layout_alignRight, which always means the right edge. Android Studio suggests the Start/End versions.

    5. Look at the output.

    Predict first

    In the next step you add a 10dp margin around the first TextView only. What do you think will happen to the second TextView?

    1. Add a margin to the first TextView:
      res/layout/activity_main.xml
      <TextView    android:id="@+id/textView1"    android:layout_width="match_parent"    android:layout_height="wrap_content"    android:layout_margin="10dp"    android:background="#0F0"    android:text="Hello World!" />
    2. Look at the output. The second TextView follows the first one: it stays below it and aligned with its right edge, even though you did not change the second TextView at all.

    Checkpoint

    • What is the difference between @+id/name and @id/name?
    • Why did the second TextView move when you only changed the first one?

    Activity 3: Basic attributes

    Three groups of attributes control how every view is sized and placed:

    • Size: match_parent, wrap_content, a fixed size in dp, or 0dp (which means “let my parent decide”, used with weights and constraints).
    • Gravity:
      • layout_gravity positions the view itself inside its parent.
      • gravity positions the content (for example the text) inside the view.
    • Margin and padding: margin is space outside the view's border, and padding is space inside it, between the border and the content.

    Why dp and not px?

    Phones with the same physical screen size can have very different numbers of pixels. A size in px therefore looks large on a low-density screen and tiny on a high-density one. A dp (density-independent pixel) is scaled for you: on screen, px = dp × (screen dpi ÷ 160). So 100dp is 100px on an mdpi phone and 200px on an xhdpi phone, and it looks about the same physical size on both. Use sp for text sizes, because sp also follows the user's font-size setting.

    Activity 3: Build a login form

    In this activity you will build the simple login form below, then read its XML to see the attributes from the notes in action.

    1. Create a new project with the Empty Views Activity template (Java).
    2. Replace the whole content of activity_main.xml with the following:
      res/layout/activity_main.xml
      <?xml version="1.0" encoding="utf-8"?><LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"    xmlns:tools="http://schemas.android.com/tools"    android:id="@+id/main"    android:layout_width="match_parent"    android:layout_height="match_parent"    android:layout_margin="16dp"    android:orientation="vertical"    tools:context=".MainActivity">​    <LinearLayout        android:layout_width="match_parent"        android:layout_height="wrap_content"        android:orientation="horizontal">​        <TextView            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="1"            android:gravity="end"            android:text="User" />​        <EditText            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="2"            android:inputType="text" />​    </LinearLayout>​    <LinearLayout        android:layout_width="match_parent"        android:layout_height="wrap_content"        android:orientation="horizontal">​        <TextView            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="1"            android:gravity="end"            android:text="Password" />​        <EditText            android:layout_width="0dp"            android:layout_height="wrap_content"            android:layout_weight="2"            android:inputType="textPassword" />​    </LinearLayout>​    <Button        android:layout_width="wrap_content"        android:layout_height="wrap_content"        android:layout_gravity="end"        android:text="Login" />​</LinearLayout>
    3. Look at the preview and compare it with the form above. Then read the XML again and find each of these ideas in it:
      • Nesting. The outer LinearLayout is vertical, so the two rows and the button are stacked from top to bottom. Each row is its own horizontal LinearLayout, so the label sits beside its text field.
      • Weights. In each row the label has layout_weight="1" and the field has layout_weight="2", both with layout_width="0dp". The label gets one third of the row and the field two thirds, so the two rows line up even though “User” and “Password” have different lengths.
      • gravity. gravity="end" on each label moves the text to the right-hand side of the label, next to its field.
      • layout_gravity. layout_gravity="end" on the Button moves the button itself to the right-hand side of its parent.
      • inputType. textPassword on the second field shows dots instead of the letters.
      • Margin. layout_margin="16dp" on the root gives the whole form some space from the edges of the screen.

    Watch out

    • A view that uses layout_weight should have layout_width="0dp". If a field had a fixed width such as 200dp, the weight would only share the space left after the 200dp, and the columns would no longer line up on different screen sizes.
    • To right-align the label text, use gravity="end". Using layout_gravity="right" on a child of a horizontal LinearLayout has no horizontal effect, because the row decides the horizontal position of each child.

    Activity 4: Constraint handles

    ConstraintLayout is the default root layout for new Views-based screens and the one you should use for most new layouts. Every view is positioned by constraints: connections from its edges to the parent, to another view, or to a guideline. It can describe complex screens with a flat view hierarchy (no nesting), which is faster to draw. It is usually built in the Design view of the Layout Editor by dragging, but it is still saved as XML, which you will read at the end.

    Tip

    A view needs at least one horizontal and one vertical constraint. A view without them shows a red error in the Component Tree (“This view is not constrained...”). It may look fine in the editor but jumps to the top-left corner when the app runs.

    1. Create a new project with the Empty Views Activity template. The main layout already uses a ConstraintLayout. Switch to Design view and delete the “Hello World!” TextView.
    2. In the Palette, open Buttons and drag a Button onto the design (or right-click it and choose Add to Design).
    3. Each side of the selected button has a small circle, its constraint handle. Drag the left handle to the left edge of the screen.
    4. The button is now attached to the left side of the screen.
    5. Do the same with the right handle, dragging it to the right edge of the screen.
    6. The button is now centred horizontally, because two equal “springs” pull it to the left and to the right.

    1. Delete the button. Now you will build a sign-in page.
    2. From Palette › Text, add a Plain Text field.
    3. Add a Password field.
    4. Add a Button.

    6. Give the views readable ids, so the XML is easier to follow: set the id of the plain-text field to usernameField, the password field to passwordField and the button to signInButton. (If Android Studio asks whether to update usages, click Refactor.)

    8. Do the same for the password field, with the hint Password.
    9. For the button, set text to SIGN IN.
